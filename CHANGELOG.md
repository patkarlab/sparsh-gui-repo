# Changes

## 1.1.0

Corrections. The default blast percentage in the settings was labelled and described as a BLAST sequence-identity threshold; it is the leukemic blast percentage that `run_sample.py` passes to the copy-number call, and it is now described as such. The blast percentage accepted whole numbers from 0 to 100, but `run_sample.py` requires a value above 0 and at most 100 and accepts decimals; the window now checks the same. Each sample's `karyotype_summary.csv` overwrote the previous sample's in the iteration's `karyotype/` folder with a warning every time; only the sample's own karyotype files are collected now. Sample names had to match what `run_sample.py` accepts (a leading letter or number) and could differ only in case from another sample although SPARSH treats such names as the same sample; both are now checked when a sample is added. After Stop, a job that was still ending could overlap the job started by the next Start in the same folder; the next job now waits for it, and quitting kills a job that ignores the termination signal. Choosing another run folder after Stop could start the first iteration of the new output folder on the previous run's BAM files, because the files found in the old folder were kept until the new one had been scanned; they are now forgotten when the run folder changes, and an iteration is opened only after a scan. The model folder was not found when the downloaded archive lay next to it, since two names matched; only folders count now. The settings file was kept inside the application folder, where uninstalling removed it; it is now in `~/.config/sparsh-run-manager/`, and an older file is read and moved there. The GitHub Actions workflow referred to files that do not exist in the repository, built for Windows and macOS although the application is Linux only, and packaged a folder with a different name from the one `install.sh` expects; it now runs `packaging/build.sh` in an Ubuntu 22.04 container.

New in the window. The reference FASTA, the EPIC manifest and the model folder can be set explicitly, so the SPARSH folder no longer needs a fixed layout (the files are still found by name when the boxes are blank, including the `hg19_main.fa` of the SPARSH README). The aligner, the number of threads, the prediction device and extra `run_sample.py` options can be set. Check setup lists the files that were found. `conda.sh` is found automatically for the usual conda installations. The sample list can be imported from and exported to a CSV or TSV file, and is written to the output folder when an analysis starts. `report.py` receives a sample sheet with each sample's sex and blast percentage, and a title naming the iteration. Start warns when the conda environment is not found and asks before creating a long-term storage folder that does not exist. The window shows how long the current step has run, opens on the Settings tab on the first start, can be light or dark, and adds a sample with Enter. Labels are written out in full (long-term storage, copy-number panel, blast percentage).

Packaging. `packaging/build.sh` builds the package, `packaging/uninstall.sh` removes it, `requirements.txt` names the dependency, and the launcher also appears in the application menu.
